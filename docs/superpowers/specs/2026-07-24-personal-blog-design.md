# 个人静态博客设计规格

## 项目背景

十一希望使用 GitHub Pages 部署一个个人静态博客，用于混合记录技术学习、生活随笔和作品展示。核心诉求是"好看、有设计感"，同时希望写作和部署流程简单省心。

## 目标

在 GitHub Pages 上发布一个温暖治愈风格的个人静态博客，支持 Markdown 写作、自动部署，并具备文章列表、标签分类、关于页面、黑暗模式和图片灯箱功能。

## 用户画像

- 具备基础 HTML / CSS / JS 知识
- 希望博客"开箱即用"且能逐步自定义
- 重视视觉设计和阅读体验
- 希望推送到 GitHub 后自动更新网站

## 技术架构

```
┌─────────────────────────────────────┐
│           GitHub Pages              │
│     （静态文件托管 + CDN）           │
└─────────────────────────────────────┘
                  ▲
                  │ 自动部署
┌─────────────────────────────────────┐
│         GitHub Actions              │
│   push 到 main 分支时触发构建       │
└─────────────────────────────────────┘
                  ▲
                  │ git push
┌─────────────────────────────────────┐
│         Astro 项目                  │
│   主题 + Markdown 内容 + 自定义组件  │
└─────────────────────────────────────┘
```

## 技术栈

| 层级 | 选择 | 理由 |
|------|------|------|
| 静态站点生成器 | Astro | 内容型网站首选，性能好、主题生态丰富、支持 Island 架构 |
| 主题策略 | 成熟 Astro 博客主题（温暖治愈风） | 快速上线，保留自定义空间 |
| 样式 | 主题自带 CSS + 自定义 CSS 变量 | 保证一致性，便于调品牌色 |
| 内容格式 | Markdown / MDX | 简单通用，适合长期写作 |
| 部署 | GitHub Pages + GitHub Actions | 免费、稳定、与代码仓库一体 |
| 版本控制 | Git + GitHub | 内容即代码，可追溯可回滚 |

## 视觉设计方向

### 风格关键词

- 温暖治愈
- 柔和配色
- 圆润卡片
- 舒适阅读

### 建议配色（可在主题基础上微调）

| 用途 | 浅色模式 | 黑暗模式 |
|------|---------|---------|
| 背景 | `#FDF8F3` 暖白 | `#1E1A17` 深棕 |
| 主文字 | `#3D3A38` 柔和黑 | `#E8E2DB` 暖白 |
| 强调色 | `#E59A5F` 暖橙 | `#F0B17A` 暖橙 |
| 辅助色 | `#8FB9A8` 薄荷绿 | `#A8D4C4` 薄荷绿 |
| 卡片背景 | `#FFFFFF` | `#2A2522` |

### 字体

- 正文：系统无衬线字体栈或主题默认字体
- 代码：等宽字体（如 JetBrains Mono、Fira Code）

## 页面结构

### 1. 首页（/）

- 顶部导航栏：Logo、首页、文章、标签、关于
- 欢迎区域：简短的个人介绍 + 头像
- 最近文章列表：标题、摘要、日期、标签
- 页脚：版权信息、社交链接

### 2. 文章列表页（/blog）

- 所有文章按时间倒序排列
- 每篇文章卡片：封面图（可选）、标题、摘要、日期、标签
- 分页或"加载更多"（根据主题能力）

### 3. 文章详情页（/blog/[slug]）

- 标题、日期、标签、预计阅读时间
- Markdown 正文渲染
- 代码高亮
- 图片灯箱点击放大
- 上一篇 / 下一篇导航

### 4. 标签页（/tags）

- 所有标签云 / 列表
- 点击标签进入该标签下的文章列表

### 5. 关于页面（/about）

- 头像
- 个人简介
- 联系方式 / 社交链接
- 可选：时间线、兴趣爱好

## 内容模型

### 文章 Frontmatter

```yaml
---
title: "文章标题"
description: "简短描述，用于列表和 SEO"
pubDate: 2026-07-24
cover: "/images/post-cover.jpg"  # 可选
tags: ["astro", "博客", "教程"]
draft: false
---
```

### 关于页面数据

使用单独的 Markdown 文件或 JSON/YAML 配置文件存储：

- 昵称 / 头像 URL
- 简介
- 社交链接（GitHub、Twitter/X、邮箱等）

## 部署方案

### GitHub Actions 工作流

触发条件：`push` 到 `main` 分支

步骤：
1. Checkout 代码
2. 安装 Node.js 和 pnpm/npm
3. 安装依赖
4. 构建 Astro 项目（`astro build`）
5. 上传构建产物到 GitHub Pages

### 域名

- 默认使用 `https://<username>.github.io/<repo-name>`
- 后续可配置自定义域名

## 开发工作流

1. 在本地 `.worktrees/feature-blog` 分支开发
2. 使用 `npm run dev` 本地预览
3. 编写 Markdown 文章到 `src/content/posts/`
4. `git commit` 并 `git push` 到 GitHub
5. GitHub Actions 自动构建并部署

## 风险评估

| 风险 | 缓解措施 |
|------|---------|
| 主题定制困难 | 选择社区活跃、文档完善的主题；保留原始主题文件便于参考 |
| 图片管理复杂 | 使用相对路径或图床；初期文章图片放 `public/images/` |
| GitHub Pages 国内访问慢 | 后续可考虑 Cloudflare Pages 或 Vercel 作为镜像 |
| 后续迁移成本高 | 内容使用标准 Markdown + YAML frontmatter，便于迁移 |
